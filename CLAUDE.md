# Size Calculator

Trade position sizing tool. No build step, no dependencies, no framework: `index.html` markup, `styles/*.css`, and native ES modules in `src/`, served as-is. Keep it that way.

## Code layout
- **Layers** (imports only point down): `src/core/` pure math and parsing, no DOM or state (bars, chart-view, black-scholes, options, sizing, stops, shorthand, futures, extended-hours, format, lev-etfs, market-data, orders, positions) → `src/lib/` store (guarded localStorage), media (DESKTOP_MQ / COMPACT_CHAIN_MQ, the SANS_FONT stack canvases draw with), delegate → `src/services/` tradier (base URL + headers, read from the settings inputs; dailyHistory, the ~1 year of daily bars both daily charts use), backup (BACKUP_KEYS payload, merge rule), sync (crypto + KV worker), schwab (tokens + Trader API via the Schwab worker); services never import UI → `src/ui/` one module per surface (risk, ticker, shares, chain, chart, daily, candles, cards, positions, position-chart, position-trade, market, tools, settings, trade, ...) → `src/main.js` boot. Each module's first line says what it owns
- **State**: all mutable app state is one object in `src/state.js` (`state.quoteData`, `state.currentMode`, ...); `createState()` lists every field with its default, `resetState()` restores them (tests). No loose globals: nothing is put on `window`
- **Events**: markup names an action, never an inline handler: `data-action` (click), `data-input`, `data-change`, `data-enter` (Enter keydown), with `data-arg` / `data-arg2` for arguments. `delegate(document, actions)` in main.js runs the nearest matching element's handler from the registry in `src/ui/actions.js`; rendered templates use the same attributes, so new cards and rows need no wiring. Adding a control = attribute in markup + one entry in `actions`. A test fails on any inline `on*` attribute or any action name without a handler (and vice versa)
- **Seams**: `onStoreWrite` (store tells sync about value-changing writes, which marks BACKUP_KEYS dirty) and `onSyncView` (sync reports status, rehydrate and pulled-toast to the settings sheet, which registers it on import). Side effects tests swap go through `effects` in `src/ui/effects.js` (copyPlainText, drawShareCard, shareCanvasToClipboard, openSim): call `effects.x(...)`, not the import
- **Types**: `core/` and `lib/` are `// @ts-check` with JSDoc; `jsconfig.json` makes editors check them. Ad-hoc full check (TypeScript is not a dependency): `npx -p typescript tsc -p jsconfig.json`
- **Running**: ES modules do not load from `file://`; serve the folder (`npm run serve` = `python3 -m http.server 8765`) and open http://localhost:8765
- **Tests**: `node --test` (Node's built-in runner, no packages). `tests/helpers/app.mjs` loads the real modules against a small fake DOM built from every `id=` in index.html and in src templates; `app({ width, fetch, storage, timers, clock })` returns `run(code)`, which evaluates with every module export in scope and state fields readable and assignable as plain variables. `width` turns on matchMedia for the layout tiers; omit it for the plain single-column app

## What it does
Sizes shares and options positions off a dollar risk amount (account size × risk %), using Tradier's REST API directly from the browser (key stored in localStorage, never in the file). Account size and risk % persist in localStorage. Risk $ (labelled "Max loss per trade") is styled as the loud number (big, bold, red — it's the max loss). Risk % preset chips: .125/.25/.50/1/2/3%, plus fixed dollar chips (default 100/250/500/1000, editable via the ✎ chip → comma list, deduped, max 6, persisted as risk_usd_presets). Active chips track whatever the current values resolve to — a $ tap can light its matching % chip too. The amount per trade must stay ONE TAP away: the risk strip (#riskStrip) is one of the FIRST things on the page (owner request: the max loss frames the trade): top of the rail on desktop, first card under the header on phones, in every mode, after only the first-run setup notice. It holds the risk $ input and both chip rows; the active chips tint red. Its summary link (#riskStatus, '1% of $50,000'; allocation mode retitles the strip 'Allocation' and swaps in #allocationControls) opens #riskSheet, which only holds the slower settings: Risk / Allocation method, account size, risk %. The strip shows in shares, options and futures, hidden in Positions, Tools and Market. Keys - and = (or +) step risk through one ladder of every preset (riskLadder: % chips at this account size ∪ your $ chips; stepRisk, no-op in allocation). There is no header risk pill (it was removed: two extra taps per change). risk_open is an orphan key from the old collapsible card.

## Architecture
- **Tradier API**: `api.tradier.com/v1` (or sandbox), Bearer auth. Endpoints used: `/markets/quotes` (greeks=true), `/markets/options/expirations`, `/markets/options/chains`, `/markets/timesales` (5min interval, for the chart)
- **Cross-device sync** (optional, off by default): passphrase-only, no accounts. WebCrypto derives sync_id (SHA-256, which KV mailbox) and sync_key (PBKDF2 200k → AES-GCM-256) — the passphrase itself is never stored or sent; the blob (buildBackup, BACKUP_KEYS = sync payload) is encrypted on-device before PUT to the tiny Cloudflare Worker in `worker/` (SYNC_SERVER is hardcoded to https://size-calc-sync.aolfat.workers.dev for now; the worker source stays in `worker/`). Every value-changing store.set on a BACKUP_KEY marks syncDirty (persisted as sync_dirty; no-op rewrites don't count) and debounce-pushes 2.5s; pushes are pull-merge-push with compare-and-swap (`PUT ?ift=<t read>` → 409 + current record if another device wrote in between; client merges and retries) so a push can never clobber an unseen change even in a same-second race — dirty keys win locally, clean keys adopt remote; the per-push dirty snapshot is restored on failure so mid-flight edits survive. An unreadable cloud blob never wedges sync: pulls report it and pushes replace it. Both sync_id and sync_key come out of the one slow PBKDF2 (512 bits split), so the public id is no cheaper to brute-force than the key. Pulls on load, focus, visibilitychange, and a 60s visible poll (`?meta=1` timestamp check first, blob only when newer; the poll also retries a failed push). last_sync_t gates re-apply; syncSuppress stops remote applies re-marking dirty; syncRehydrate re-reads storage into the UI without a reload (keeps the loaded ticker input). Enabling adopts the cloud copy when one exists, else seeds it. Wrong passphrase = different id = 404, reads as empty. sync_id/sync_key/sync_dirty/last_sync_t are device-local, never in the payload (sync_url, saved_positions and deleted_positions are no longer read: orphan keys on older devices). Worker: GET/PUT one `{t, blob}` record per id in KV, 200KB cap, 400d TTL refreshed on write, sees ciphertext only
- **Schwab trading** (optional; new trades are shares only, risk sizing only; held positions get a breakeven stop and a close from Positions): the shares card's **Trade at Schwab** button (#sharesTrade, shown only when connected, in shares mode with risk sizing, for stock/ETF quotes; disabled without a valid stop) refreshes the quote, then opens the review sheet (#tradeSheet, SHEETS.trade). buildTradeTicket freezes one ticket from sharesPlan() (the same math renderShares shows): qty, the stop snapped to Schwab's tick toward the entry (stopTick: cents at $1+, 4 decimals below), and the exact payload (sharesStopOrder: MARKET DAY entry, orderStrategyType TRIGGER, child STOP for the same shares; long = BUY → SELL, short = SELL_SHORT → BUY_TO_COVER). The stop lasts Today or Until canceled (schwab_stop_duration, default GOOD_TILL_CANCEL); the entry is always DAY. sharesTicketError blocks a stop already through the bid (long) or ask (short), sub-one-share sizes, and non-stock types. Warnings: outside 9:30–16:00 ET weekdays (no holiday table), risk at the current ask/bid >10% over the plan, a same-symbol order in the last 2 minutes. Place sends the frozen payload ONCE (ticket.sent) and nothing retries it; a network failure says to check Schwab before retrying. After a 201 the order id comes from Location and one status read reports fill and stop status (↻ Status re-reads). Login: Settings → Schwab trading takes the worker URL, Log in opens `<worker>/login?state=…`, the user pastes the callback address (https://127.0.0.1 style), or the app finishes by itself when its own URL is the callback (initSchwab reads ?code, requires the stored state, strips the query). Tokens (`schwab_tokens`: access ~30 min, refreshed with a 2-min margin through one shared in-flight refresh; refresh ends 7 days after login), accounts (hash + last 4 only), and the chosen account are device-local: not BACKUP_KEYS, so never in backups or sync. `worker/schwab/` is a second Cloudflare Worker (separate from the sync worker, which stays ciphertext-only): `/login` redirect, `/token` and `/refresh` with the app secret (Basic auth, only access/refresh/expires_in returned), `/trader/v1/*` relay passing the bearer through and exposing Location; browser calls only from ALLOWED_ORIGINS; it stores nothing. Positions reads and trades through the same login (see Positions). No Schwab sandbox exists for individual developers: every order is real
- **Stops**: ONE global stop pair in the ticker card, used everywhere. Long stop (shares-long + calls, blank = LOD) and short stop (shares-short + puts, blank = HOD). Only the stop matching tradeCtx() is shown/drawn (shares follow the Long/Short toggle, options follow chain side; Both view shows both). Chart click sets the context's stop; in Both view, below price = long, above = short. Quick lookup uses the pair when its ticker matches the loaded quote, else that underlying's LOD/HOD. Inputs clear on symbol change
- **Stop adjustment strategies**: selector below the stop inputs offers None (default), 5m ATR, and Percentage. ATR keeps its 0.25× / 0.5× / 1× / 1.5× / 2× chips. Percentage offers 0.025 / 0.05 / 0.1 / 0.25 / 0.5% presets plus a custom input (0 ≤ percent < 100). The percentage is of the LOD/HOD price, not entry-to-stop distance: long stop = LOD × (1 − percent / 100), short stop = HOD × (1 + percent / 100). Each strategy remembers its amount; None retains both. `stop_strategy`, `stop_percent`, and `atr_multiplier` participate in backup/sync. Existing ATR-only settings restore as ATR when nonzero, otherwise None. Manual/chart-set stops override either strategy. Nonzero buffers round outward to cents and feed shares, reverse sizing, option estimates, copy/image output, both charts and their click mappings. Invalid inputs or nonpositive stops block automatic sizing. Percentage works without ATR data; quick lookup for another ticker only fetches ATR when the ATR strategy is selected. Pinned buffered stops are labeled fixed and retain their numeric price on refresh; unadjusted LOD/HOD cards retain live-level behavior. Presets are experiments, not backtested recommendations; price adjustments cannot confirm a 5m close. Tests: `node --test`.
- **Five-minute ATR calculation**: long stops use LOD minus multiplier × ATR(14); shorts use HOD plus the buffer. ATR uses regular-session native 5m bars, 14 true ranges seeded with a simple average then Wilder smoothing, including gaps from the previous session. API epoch timestamps exclude incomplete bars. A fixed 14-calendar-day fetch keeps the seed independent of the visible 5/15/30/65m chart interval. The readout includes the last completed bar's date/time. Missing ATR blocks automatic sizing only for the ATR strategy. Formula reference: https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/atr; candle timestamps: https://docs.tradier.com/docs/timesale
- **Shares mode** (default): Shares = risk$ / |entry − stop|. The Long/Short toggle lives FIRST in the Entry & stops row (direction is the first decision; dirField hidden in options mode where chain side plays that role)
- **Allocation sizing**: Risk remains the default on load. Allocation uses `floor((account × allocation% − existing exposure) / unit cost)`, floored at zero. Long shares use planned entry (current quote if blank), long options use full mid debit × 100, and explicitly selected **Sell put** uses strike × 100. Target allocation % is persisted/backed up/synced as `calc_allocation`; manual existing exposure is session-only and keyed by ticker (shares at current value + short-put assignment notional + long-option debit). Total allocation includes existing exposure. Editable quantities change allocation %, leaving risk settings intact. Futures and short shares switch to Risk; spreads keep defined-risk sizing. Allocation ignores chart stops. Switching away from Options clears sell intent.
- **Allocation option cards**: chain detail can pin a trade; quick lookup captures the current sizing mode and buy/sell choice before fetching. Cards retain `sizing:'allocation'`, `shortPut`, and `credit` after global mode changes. Only verified stock/ETF underlyings, matching standard roots, and 100-share contracts are supported; invalid/crossed/missing/zero-bid quotes and expired contracts cannot size a new trade. Missing Greeks do not block sizing. The put panel shows assignment notional, premium, basis/breakeven, maximum loss at zero, and return on full notional; simple annualization is unavailable at zero DTE. DTE uses the New York calendar. Exposure remains manual. Copy, image, and simulation preserve side; short-put simulation returns use strike notional. No broker BP estimate, 50%-capital return, return/delta score, or assigned-call preview in v1.
- **Options mode**: straddle T-chart — calls left, strike center column, puts right, mirrored columns (Cts, Loss/ct, OI, Vol, Δ, Mid | Strike | reversed). Single-side views (Calls/Puts) use a wider layout with bid/ask/IV/@stop/total. Mobile (<500px) shows OI/Vol/Δ/Mid per side (m-size hides Loss/Cts/Total — sizing lives in the tap-in detail; m-oi and m-delta re-shown) and compacts number formats; colspans both 9 / single 5 / banner 4. Chain header is locked while scrolling: sticky thead — on desktop the chain is its own scroll panel (.chain-scroll, max-height ~100vh); on mobile (table fits, no scroll wrapper) it sticks to the page below the context bar (--sbh offset)
- **Share cards**: the shares sizing card has separate **Copy card image** and **Copy summary** actions, disabled when the stop is invalid. Image copying (also available as 'share' on pinned cards) renders a hand-drawn canvas PNG (drawShareCard — deliberately NOT a DOM screenshot: no deps, Safari foreignObject is unreliable) via ClipboardItem (promise constructed inside the gesture for Safari); falls back to downloading the PNG. Shares images label custom stops explicitly and retain percentage-based risk/position values and the $10k-account example. Copy-as-text one-liners (copyShares/copyPinned) state risk as % of account and end with a $100-risk example (ex100: units for $100, or the one-unit risk when a single unit exceeds it)
- **Simulate returns**: Black-Scholes (normCdf via Abramowitz-Stegun, RISK_FREE 4%) canvas modal — return % over time (now → expiry) at a slider-chosen underlying price, IV held constant. Green above breakeven / red below via canvas clipping, max-loss floor, drag crosshair readout (est $/ct, %, $ P&L × qty). Price chips: stop / now / 1R / 2R (R = distance to stop, side-aware). Entry points: chain detail row (simReg by OCC symbol), pinned cards (entry = mid). Esc closes
- **Option loss model**: Black-Scholes move applied to the market mid — `premium@stop = max(0, mid + BS(stop,T) − BS(spot,T))` so IV-skew level offsets cancel; falls back to Δ+½Γ·move² when the contract has no IV (model flag 'bs'/'approx'). Clamped so a loss-direction move can't show a gain. loss/ct = (mid − premium@stop) × 100, contracts = floor(risk$ / loss per ct). Calls priced off the long stop, puts off the short stop. Mid cells flag wide spreads (>10% of mid) in amber
- **Overnight line**: every loss@stop also computes premium@stop at T − 1 day (atStopON/atLodON). Detail rows and cards show a quiet 'held overnight: −$X (−Y%)' line when it's worse than today's — no controls; 0DTE naturally shows full loss to intrinsic
- **Expected move**: ATM straddle mid for the loaded expiry, shown in the filter row (emInfo), computed pre-zone-filter
- **IV percentile**: ivInfo in the filter row shows the loaded expiry's ATM IV ranked against the past year's rolling HV20 distribution (hvDist, from the 380-day history fetch). Amber ≥80th (rich), green ≤20th (cheap). True IV Rank isn't available from Tradier (no historical IV endpoint); an own-IV diary was tried and removed by request
- **HV20 + prior day**: fetchAdr's daily history also yields hv20 (annualized 20d stdev of log returns) and prevDay {h,l,c}. Detail rows show IV vs HV20 (amber >1.5×). Chart draws PDH/PDL/PDC gray dashed lines when inside the visible range
- **Recent tickers**: last 5 symbols as chips under the symbol row (recent_tickers, MRU, current excluded). Chain auto-scrolls to the ATM row on user-driven loads only (pendingAtmScroll — never on live polls). Live mode is a duration ladder: tap ⚡ for 1m @ 5s ticks, tap again to extend 5m @ 10s, again 30m @ 20s, again stops (LIVE_MODES). Refreshes pinned cards every 4th tick offset from the chart. Backgrounding PAUSES the session (remaining time kept) and returning resumes it
- **Reverse sizing**: Shares stat and Contracts stats (detail row, pinned cards) are editable inputs; committing a quantity writes risk$ back (riskForQty) and everything re-renders from it. Quantity floors use unitsFor (epsilon-tolerant) so counts round-trip exactly
- **Zone filter deltas**: filtering uses a BS-computed delta (filterDelta — Tradier greeks can print flat 1.000 across all ITM strikes, defeating any threshold); the Δ column still displays the API value
- **Zone filter**: radio segmented control (zoneMode: otm | itm | both | all → derives zoneFilter) — OTM (|Δ| ≥ .20 floor), ITM→ATM (a DEPTH LIMIT: |Δ| ≤ setting, default .80, band runs from the ATM strike down to it; ATM strike always shows with a blue ATM badge; deeper = All view), Both (union → contiguous band around ATM), All (no filter). One mode at a time; each Δ floor input only visible when its zone is active. Keys 1/2/3/4. ATM strike computed from the full chain pre-filter. Zones apply ONLY to single-side views. The Both-sides T-chart ignores them entirely and instead shows a configurable window of ± N strikes around ATM (bothStrikes input, default 8, persisted as both_strikes; zone seg + floors hidden there via updateChainControls). Any zone pick (chip or keys 1–4) from Both view switches to Calls first; the chosen zone mode is remembered across side switches
- **Entry price**: optional underlying entry input (blank = current price) in the Entry & stops row, amber border/line (blue collided with VWAP). Shares size off |entry − stop|; chain prices premium@entry via the same BS move and losses run entry→stop (entryPrem is the cost basis for cts/total/loss%). Drawn on both charts, cleared on symbol change; sim uses entryPrem
- **Loss/ct cells** show dollar loss with % of premium lost stacked below, color coded (green <25%, amber 25–60%, red >60%)
- **Vol/OI**: bold columns with blue tint, resting in muted gold (--gold #d9b968); BOTH turn full amber together when vol > OI (the signal is about the pair — they're always read together). This emphasis is intentional — don't tone it down
- **Expirations**: tabs with a DTE line under each date, monthlies (third Friday, or Thursday-before if holiday) badged amber with "M" corner tag. Shows 12 + "+N more" expand
- **Quick lookup**: the ticker field is ALSO the search box: submitTicker routes a single word to fetchQuote and anything with spaces to fetchQuickOption(text, fromSearch) — which pins the card, puts the loaded symbol back in the field, and scrolls the new card into view on phones. #tickerParsed under the field previews the pin ('Pin AAPL $245 call …'), says what's missing, or shows the shorthand hint. On phones the separate Quick lookup card is hidden (the field does it); desktop and tablet keep it. Order-free shorthand parser — tokens classified by shape (ticker / strike / date / call-put, and a strike may carry its type: 245c, 580.5p), any order, `/` or `.` date separators ("AAPL 245 6/20", "9.18 300 aapl", "SPY 580 put 6/18/26") → OCC symbol → pinned result cards, newest on top. Dotted number = date unless a date is already set (then strike); bare c/p = type only when another word can be the ticker. Spread shorthand: a slashed strike pair (105/115 — anything slashed that can't be a date) or two bare numbers plus cds/pds/ccs/pcs ('rbrk 105/115 8/28 cds') → spread pinned card; second letter d = debit, c = credit. Near strike first either way: calls take the lower, puts the higher (debit buys it, credit sells it); both legs fetched in one quotes call, a pair whose near mid isn't the richer rejected. A pair without a spread token parses as '?'
- **Verticals — debit and credit spreads** (two-leg, the only multi-leg supported): '+ debit spread' / '+ credit spread' in a single-side detail row marks the near leg (detailReg by OCC symbol), a banner asks for the far strike (calls higher, puts lower, both kinds), tapping a row completes it (direction and net > 0 validated; Esc or side/mode/chain changes cancel via cancelSpread). Spread cards are pinnedData entries with kind:'spread' + legs[{K,iv,side,occ,mid,delta}]; legs are ALWAYS the debit-spread legs (near +1, far −1) and d.mid = their net (= the debit paid, or the credit received) — a credit spread is just credit:true on top, i.e. SHORT that debit spread. cardValueAt(d,S,T) nets the legs' BS values and recalcPinnedStop/sim math all run through it, so stop-value, overnight, P&L, and the simulator (legs-aware simCurve) just work; refreshCardData is untouched by credit. The credit flag only flips signs and words at the edges: isBull(d) picks the stop side (call credit = bearish → HOD/short stop) and the losing direction, recalcPinnedStop clamps the other way (a loss move can't get cheaper to buy back) and caps spread value at width, loss/ct = close@stop − credit, lossOfCost = % of max loss. SIZED BY DEFINED RISK (sizeUnit(d)): full debit, or width − credit. Sim return % basis for credit = max loss, so the −100% floor and full-credit max profit fall out naturally; 1R/2R chips and sim direction follow isBull. Debit card leads with max profit; the credit card instead shows an always-visible Max loss / spread stat (max profit = the credit = stat 1) and the credit as % of width (on the pinned stat and share image). Breakeven (near K ± net, same formula both kinds), reward/risk; direction tag color follows isBull. Share/copy label as '100/110c debit spread' / 'sold … credit spread'
- **Tools**: the header tabs ARE the top-level nav — 'Market / Size / Positions / Tools', keyboard-accessible buttons with aria-current on the active one. On phones (≤600px) the same buttons become a fixed BOTTOM tab bar with icons (.tab-icon, hidden elsewhere), clear of the home indicator via env(safe-area-inset-bottom) (viewport-fit=cover), hidden while a field has focus so the keyboard owns the bottom; the header then shows the screen title (#viewTitle, set by setView) and the settings button. Click Size = calculator, click Tools = tools view (setView 'utils', keys t or u toggle tools ⇄ size). Tools view hides ALL calculator surfaces including the ticket card. Currently holds the % gain card (bought at / current price → gain %, per-unit change, multiple; renderGain, no API) and the leveraged ETF finder — add future small tools here
- **Leveraged ETF finder** (tools view): type a stock/index → its leveraged ETF family ranked by liquidity. LEV_ETFS is a CURATED static map (underlying → [sym, daily leverage], longs first; ~175 underlyings / ~385 ETFs after a full issuer sweep (Direxion, GraniteShares, ProShares, Defiance, T-Rex/REX, Tradr, Leverage Shares, Corgi, Volatility Shares, Roundhill) + index/sector/commodity/crypto/VIX; expect to keep adding — issuers launch and liquidate constantly (ARMU, Direxion's Apr 2026 bears, and REX's SOL/XRP funds all died in 2026); verify tickers via web search before adding, don't guess), LEV_ALIASES folds SPX/ES/VOO→SPY etc., LEV_REVERSE resolves a typed leveraged symbol to its family (TQQQ → QQQ set, with a note). Both/Long/Short seg (levDir) is a display filter over the last result (levLast re-renders without refetch; cleared on empty/no-match so a toggle can't resurrect a stale table). With a key, one /markets/quotes call ranks by dollar volume/day (average_volume × last, today's volume fallback); spread % of mid amber >0.25%; top long and top short get best-long/best-short badges (.lev-badge). No key = static list, unranked. Rows are tap-to-load: levLoad puts the symbol in the ticker field, jumps to the calculator, fetches when a key exists. Leverage labels are static and can drift when issuers change factors — quotes are live, labels aren't; a delisted map entry just quotes empty and sinks to the bottom
- **Lev ETF price target** (tools view): type a mapped leveraged ETF + a target price on its underlying + days → expected ETF price. Requires a key and a LEV_REVERSE symbol (typed underlying hints its family instead, no manual fallbacks by request). One quotes call for both symbols; days ≤ 1 is the exact daily reset (etfNow × (1 + lev·move), floored at 0); days > 1 applies GBM vol drag `gross^lev × exp((lev − lev²)/2·σ²·days/252)` with σ = underlying HV20 from a 60d /markets/history fetch (hv20At, extracted from applyDailyHistory and shared; too little history = drag skipped and noted). Stat grid: ETF at target (good/danger), ETF move %, underlying move %, and a Decay cost stat (vs the no-drag number) when days > 1. Estimate only — theta-free, IV/fees/borrow ignored, real chop drags more
- **Market**: full-width view (`setView('market')`, key m) with five category tabs: Theme Tracker (146 industry groups / 2,860 stocks), Group ETFs (88), S&P Sectors (17), Equal Weight (13), Country ETFs (28). Two CSV snapshots in `data/` load together; partial load failures can be retried. Tabs have arrow/Home/End keyboard navigation. Table and heatmap share period/sort/search state; changing categories clears search/drilldown and keeps compatible periods. Theme rows use Today/1W/1M/3M/6M/YTD; ETFs use From open/Today/1W/1M/3M/6M/1Y, preserving the reference's Perf Year separately from YTD. Selecting a group drills into stocks; selecting any stock or ETF returns to sizing and clears old quote/stops. `/` searches, Escape returns from a group, r refreshes quotes for the active scope. `MarketData` is a pure inline script tested by `node --test`; no build/dependencies. Snapshot dates are explicit. Auto refresh defaults on with a configured key: active ETF category / opened group every 30 seconds, full Theme Tracker every three minutes after completion. Refresh quotes uses the same scope, preserves period/sort/search/table scroll/focus, commits atomically, and caches per scope and environment outside sync (v3, with v2 migration retaining timestamps). Cached quotes appear immediately with age/coverage/stale labels; a group can reuse a newer full-theme cache without making the overview appear fresh. One batched Tradier POST refresh runs at a time (100 symbols/batch, 1.25-second spacing); scope/view/visibility/offline changes cancel it. Failed batches retry twice with cancellable backoff, rate-limit headers are honored, exhausted failures back off 30 seconds–three minutes, and auth failures pause Auto. Auto off / Cancel pauses polling; Use snapshot also restores the imported data. Returning refreshes only stale scopes. Missing refreshed quotes become unavailable, never old-snapshot fallbacks. From open is `(last/open - 1) * 100`; longer returns stay imported. Calculator charts and sticky bar stay hidden in Market, including pending quote callbacks, and calculator live polling pauses while Market is open. See `data/README.md` for sources, updates and validation.
- **Positions** (Schwab, read-only): a top-level header tab (Positions, count badge #posCount = rows in the last read, key v), not part of the instrument switcher. positionsView is a display state, NOT a mode — currentMode stays shares/options underneath (tradeCtx etc. unaffected); selecting it hides all sizing surfaces (including the ticket card) and shows #positionsSection only: a live table of the account picked in Settings → Schwab trading, straight from Schwab (no Tradier key needed). Two reads per refresh: `GET /accounts/{hash}?fields=positions` (schwabPositions) and the last 59 days of orders (schwabRecentOrders; Schwab's window is 60). Columns: Symbol (options as 'AAPL 6/20/26 245C' from Schwab's padded OCC symbol), Qty (shorts negative), Avg cost, Price (market value / qty × multiplier, Schwab's own mark), Market value, % of acct (of liquidation value, not the risk strip's account size), Stop, Risk @ stop; total row sums value and loss-only risk. No P&L columns by request. core/positions.js (pure, tested): workingStops walks orders and their childOrderStrategies (so the stop half of a filled TRIGGER counts) for resting single-leg STOP/STOP_LIMIT orders whose instruction closes the position (SELL/SELL_TO_CLOSE on longs; BUY_TO_COVER/BUY_TO_CLOSE/BUY on shorts; AWAITING_PARENT_ORDER excluded). Nearest stop leads; each fills against the shares the ones before it left. Risk = (avg − stop) × qty × multiplier from YOUR average cost (side-aware), negative = green 'locked'; 'covers X of Y' when stops cover part; blank without a stop or cost basis. Both re-read Schwab first, then freeze a ticket from pure plans in core/positions.js. breakevenPlan: a breakeven stop on every share/contract at row.be (stocks stopTick toward the market, options optionStopTick: $0.05 under $3, $0.10 from $3, the grid every option class accepts, so up to a dime better than cost) without ever asking Schwab to sell more than you hold, which it refuses through the API ('may result in an oversold/overbought position'). The shares outside any limit target (rest) get one plain stop. When another order already closes part of it (closersInTheWay: limit targets, pair legs, anything else waiting), the sheet asks first and sends nothing until answered (setPositionBeMode, t.choose / t.mode, nothing preselected; an option that can't work is greyed out with its reason): **Stop the rest** (breakevenPlan(..., { limits: 'keep' }): the limits stay as they are and their shares (plan.bare) keep no stop; greyed out when a limit holds the whole position), **Pair with the limit** ({ limits: 'pair' }, the default: the shares a limit holds get a stop paired with that limit as an OCO, one cancels the other), or **Cancel the limit** ({ limits: 'cancel' }: every other closing order is cancelled, limits and pairs first, then the extra stops, and the nearest stop is replaced to cover the whole position; also the way out when a market or other order blocks the first two). Positions with nothing in the way get no question. Steps: cancel the limits being paired (and pairs whose stop isn't at breakeven), cancel the extra plain stops farthest first, replace (or place) the nearest plain stop for the rest, then place each limit again as OCO(limit, BE stop); paired shares have no stop for a moment and the sheet says so. A paired limit takes the stop's duration and regular hours (warned when that changes it). Blocked when the price is through the stop, without a cost basis, for fractional shares, when another kind of order (market, etc.) is waiting to close part of it, when the closing orders already exceed what you hold, or when every share already has a breakeven stop. closePlan: cancel every order in play that closes it, targets first and the nearest stop last, then a MARKET DAY close (SELL / BUY_TO_COVER / SELL_TO_CLOSE / BUY_TO_CLOSE); a failed cancel means no close. An order is in play unless FILLED / CANCELED / REJECTED / EXPIRED / REPLACED / AWAITING_PARENT_ORDER (so NEW, PENDING_*, QUEUED... count); restingOrders tags OCO legs with their pair. A cancel Schwab refuses is fine when a GET shows the order already gone (an OCO leg cancelled with its pair) and stops everything when it FILLED. No plan when the orders read failed (stopsMissing). Steps run in order, stop at the first failure, are sent once (ticket.sent), never retried; afterwards Schwab is re-read and the sheet says what it now shows ('Schwab now shows stops at $38.20 for all 300 shares', how many shares have no stop, a limit cancelled and not placed again). No stop = the limit alone. ## Conventions
- Dark trading-terminal theme, CSS variables in `:root`, tabular numerals for all figures. One font for everything (owner request: cleaner): Geist (`--sans`), self-hosted in `fonts/` (latin-subset variable woff2 from Google Fonts, 400–700, OFL in fonts/OFL.txt, preloaded in index.html; missing glyphs like Δ and arrows fall back to the system font). Figures keep columns lined up through tabular digits, not a monospace: a universal `font-variant-numeric: tabular-nums !important` (the `font` shorthand would otherwise reset it). Figure styles use `--num` (= `--sans`; point it at `--mono` to bring back the monospace terminal look); `--mono` is the system monospace, only for the order payload JSON. Buttons and inputs inherit the family. Canvas text (charts, sim, share image) can't read CSS variables, so it uses SANS_FONT from `src/lib/media.js`; change both places together. Canvas has no tabular-digit switch, so canvas digits are proportional. Labels, section titles, and stat labels are sentence case (no tracked caps); dense table headers stay small caps. Helper copy is short sentences; longer rules go in a <details class="hint-details"> disclosure
- The shares answer is its own card (#sharesSection, class card) right after the ticket inputs, outside #quoteSection, so setQuoteVisible/updateModeSections drive its visibility. Shares sizing leads with an editable share count and equally prominent **Stop price**, followed by risk at stop, position value, and risk per share. Entry sits under shares; the stop source is **Custom stop** for an explicit input, otherwise **Low of day (LOD)** or **High of day (HOD)** according to direction. Never infer the source from price equality. Image and summary actions sit in the footer.
- Desktop shell (≥1100px, calculator and Positions only, media-only — no toggle): .app becomes a 100vh grid and the PAGE HOLDS STILL; each pane scrolls on its own (no position:sticky anywhere — sticky charts once shifted against the page; don't re-add). Panes: #sidePane = #railPane (setup notice, #riskStrip, ticket card #modeCard, shares answer, #optionTicket, futures) over #trayPane (quick lookup, pinned cards); #mainPane = kbd help, quote card, charts, chain (and the positions table in Positions, which spans the full width). Tools, Futures and Market scroll as a normal page at ≥1100 but keep the shell's full-width header at the same position and height (`.app > .header`), so switching views never moves the tabs; their content is a centered column (888px; Market 1468px). ≥1800px: #sidePane goes display:contents and the tray becomes its own right column (360 / 1fr / 340). Below 1100 every pane wrapper is display:contents and .app is a flex column, so the cards are flex items placed by `order` (setupNotice, riskStrip, modeCard, quoteCard, sharesSection / futuresSection, chartWrap, quick lookup, pinned, positions, then optionsSection). Chain tiers: COMPACT_CHAIN_MQ (1100–1439) keeps the compact columns (twoPaneChain(), isMobileChain() true, Δ/OI re-shown, colspans both 13 / single 8 / banner 6, charts stacked 5m first); ≥1440 the main pane is ~1000px so the full table returns (min-width dropped to fit, charts side by side). CSS mirrors DESKTOP_MQ / COMPACT_CHAIN_MQ exactly. On desktop, tapping a chain contract fills the rail ticket (#optionTicket via detailBody/showDetail, railDetailSym, re-armed on re-render, cleared by closeDetails) instead of an inline row; phones and tablets keep the inline detail row. - Keyboard help card is grouped (navigate / views / chain / data)
- Mobile rows (≤600px): preset chip rows (#riskPresets, #riskUsdRow) are single-line EQUAL-SPLIT thumb-sized chips (flex 1 1 0, 36px tall, labels hidden — % and $ speak for themselves; nowrap !important over .chip-row's default wrap; the desktop rail splits them the same way); #recentTickers stays side-swipe (unbounded list). - Big Shares / Options / Futures segmented switcher at top of ticker card — keep it prominent
- localStorage wrapped in try/catch (`store` helper) so sandboxed previews don't crash
- PWA: manifest.json + icon-180/512.png + sw.js (network-first, same-origin GETs only — API calls pass through; cached fallback offline). Registered only on https. Fixes iOS home-screen staleness — fresh version on every online open
- Durability: navigator.storage.persist() requested at init. Export/Import backup buttons in the Settings sheet (BACKUP_KEYS → JSON file + clipboard; import overwrites those keys, reloads). Backup file contains the API key — hints tell the user to keep it private. Green toast variant: .error.ok via showToast()
- iOS home-screen meta tags present (apple-mobile-web-app-*) — file is meant to be hosted (GitHub Pages) and added to iPhone home screen
- Wheel over a focused number input blurs it so the page scrolls instead of spinning the value
- Owner's style: direct, terse. No em dashes in user-facing copy.

## Known caveats / next ideas
- Loss model includes gamma but still ignores theta/IV shift — noted in detail rows, fine for intraday sizing
- Last ticker persists in localStorage and auto-loads on open when a key is saved
- `timesales` needs a Tradier brokerage-linked production key; chart hides quietly if unavailable
- If hosted-page CORS to api.tradier.com ever fails, fix is a small Cloudflare Worker proxy
- Possible future: stop-on-premium mode (vs stop-on-underlying), condensed mobile column set for <500px, OI static intraday (OCC settles overnight)
